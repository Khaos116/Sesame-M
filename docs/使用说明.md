## SJ 3.6.67 新增功能怎么开启（2026-10-08）

运行日志里“全部任务已执行完成”只表示调度结束。神券会逐项写明任务跳过原因与抽奖次数回查。失败不记成功，授权失效/切号/取消仍终止。独立福利缺少必要状态不记查询间隔；普通RPC业务拒绝不再三次停一天，实际风控和验证仍按接口处理。旧未知写回执保留，勿为重试清空账号状态。

先进入当前账号对应类别，开启模型与下列具体开关，修改后用返回键保存。所有新功能开关默认关闭；SJ新增活动及好家缴费金每日预算默认30，旧卡20、农场访问20、余额宝免费任务20、金豆小游戏1、临期道具1。已有账号保存的预算不自动覆盖；0仍可主动停用，资产兑换/捐赠额度不随这些任务次数增加。

| 类别 | 新功能 | 必要配置 |
|---|---|---|
| 其他 → 其他任务 | 神券签到、浏览/搜索与抽奖；花呗亲密度浏览；玩赚签到；乐游记浏览/骑行 | 开对应开关，并设置「SJ新增活动｜每日操作尝试预算」，默认30、范围0～50，0不执行；每次签到、报名、上报、领奖、抽奖、兑换或骑行会话各计一次 |
| 其他 → 其他任务 | 里程兑换出行券 | 除开关/预算外，填写自己明确选择的商品编码（逗号分隔）和6位城市编码，默认空，不沿用作者商品 |
| 金豆 → 金豆夺宝 | 三款小游戏前台操作 | 开「前台小游戏自动操作」，每日尝试上限1～3；亮屏解锁，允许打开小游戏，失焦、锁屏或窗口身份不明停止 |
| 农场 | 当前任务列表浮球时长、手动访问领奖 | 浮球还需开「农场任务」；设置「农场访问扩展｜每日操作尝试预算」默认20、范围0～30，0停用，共用预算；60秒浮球至少4次（启动、两段30秒、完成），手动领取1次 |

神券抽奖默认保留SJ的四川泸州固定位置，不读取GPS，也不会因为手机在国外而改用海外地址。只有抽奖使用该JSON，签到/浏览不需要。接口是否接受海外账户或海外网络未实测；需要调整时才编辑定位JSON。

神券运行日志记录开关/日预算、接口名、是否进入查询或写RPC、成功标记/业务码、签到资格/任务状态/抽奖次数及回查结果。`未调用RPC`表示在调用前停止；`已进入RPC`只表示调用开始，不代表服务端已经执行成功。数量`-1`表示字段缺失或无效，不当作0。预算为0、额度耗尽、任务被过滤和记录保存失败均说明原因；不输出授权码、Token或响应正文。

神券按SJ显示具体任务：`神券团购任务[名称]：上报已受理，开始等待…秒`表示尚待确认；`✅ 神券团购完成任务[名称]得[奖励名称]（已回查确认）`才表示该任务领奖完成。抽奖逐次显示服务端返回的奖品名称，缺少名称时明确显示“未提供奖励名称”，不猜奖励。“此前已完成并领奖”表示之前的状态，不是本轮新完成。`MGW200`是这些上报/领奖接口的成功码；`131853`及之前构建曾误判该码，需使用后续修订包。

好家签到/浏览/领奖的确认结果同时写入运行日志和分类日志，以`✅ 好家缴费金｜任务名：浏览完成 · 待领奖（已回查）`或`领奖成功 · 余额=…→…（已回查）`显示；签到显示“签到成功”和余额。`☑️`标记读取时已完成的旧任务，不能当成本轮新增；`📊`进度分两行显示完成/领奖与剩余，结束只汇总本轮新增及余额，不重复整张目录。正常查询不再重复刷长接口字段，写调用、异常、失败码和必要回查原因仍写运行日志。本轮执行顺序是好家缴费金、卡片奖励、神券团购；浏览任务按服务端时长等待，日志中途导出时后面的活动可能还未开始。

神券、好家回查确认的成功结果前加`✅`；神券仅上报确认、尚待领奖用`📤`，受理响应或查询成功不表示任务领奖成功。神券汇总“本轮新完成并领奖”和“此前已完成并领奖”的项数；好家汇总本轮新完成浏览、本轮新领奖及余额起止，并显示最近回查的总目录/已完成/已领奖/待领奖/剩余未完成/剩余可免费浏览/需人工或不支持/未知状态。只在进度变化时打印查询统计，16项目录不变也能看到完成和领奖增加；未知状态单列，不算已完成。总目录包含已完成和不符合免费规则的任务，条目数不随完成而减少。未执行时显示配置关闭、已有尝试、未确认回执、当日检查结束、预算耗尽、未到期或无可领奖励，不能把检查结束或旧状态当成本轮成功。

「其他任务」离线或处于只收能量时段时，入口日志显示原因。风控退避统一由现有RPC保护按账号、接口处理；某活动被拒绝仍结束本轮执行，但不再额外把所有其他活动暂停24小时。神券、好家和旧卡的拒绝日志显示活动/接口标签；具体接口仍可能因原有RPC退避而跳过。独立福利任务仅在本轮请求正常返回后记录配置的查询间隔，默认6小时；网络、解析或明确业务失败不再提前记间隔，也不额外加6/12/24小时暂停。查询间隔拦截时显示剩余秒数。

新版不再读取旧的OtherTask.nextRun整模块暂停，也不读取独立福利任务旧nextQuery/nextSuccessfulQuery/cooldownUntil，改以nextConfirmedQuery记录通过业务校验后的正常查询间隔；不需要清空账号状态。RPC保护和其他模块已有暂停、每日预算及未确认记录继续保留；接口冷却或查询间隔表示尚未到再次请求时间，不表示已经提交或领奖。早先180837及之前构建仍有旧暂停逻辑，应以新版日志判断当前阻断原因。

RPC暂停或GR已知异常规则跳过时，原因中显示具体接口名；“全部任务已执行完成”只表示本轮调度结束，各功能是否成功以自己的结果日志为准。运动同步步数显示目标步数、宿主类加载/方法匹配/调用及返回阶段；目标步数不是错误码。账单贴纸显示领取、升级权益或免费抽奖阶段；成功查询没有待领列表、普通贴纸或抽奖机会时只跳过空项，继续后续检查，错误类型和提交后的必要回查仍停止。

神券有待核对记录时，同日先按原操作查询；机会领奖以唯一匹配任务RECEIVED/DONE为准，不额外要求余额增加。跨日旧记录先查当前活动并归档原记录，历史结果未确认不记成功；仍未知的旧任务当天仅隔离对应playId，签到/其他任务/免费抽奖按当前资格继续。同日未知抽奖、错账号、未来/无效日期、损坏记录或查询/归档失败仍保留，不清空账号状态或预算。日志显示归档、具体操作和回查状态；调用前被上限/冷却拒绝时，不新增额度或待核对记录。

神券签到提交回执失败但有效回查明确本账号今日已签到时，会记录原失败码、清除待核对记录后继续任务/免费抽奖，不重复签到。签到仍未确认时只保留签到回执、停止重复签到，按SJ继续检查其他任务及已有免费次数；次数增加不能代替签到成功证明。旧同日签到回执原样迁到独立位置，保存失败或冲突仍保留原记录并停止。未知抽奖、损坏共享记录、切号跨日或确认记录清除落盘失败仍停止；签到RPC原有保护与其他接口分别处理。

同日神券浏览/搜索或机会领奖未确认时，只保留并限制该任务playId，继续其他任务及已有免费次数抽奖；旧版本的同日全活动任务回执先原样保存到对应任务，再清除原位置，保存失败或记录冲突仍停止。签到和抽奖的未确认记录仍需要先回查。好家缴费金、旧卡、SJ活动组和好家无忧分别计算每轮请求数，保留原80次上限及RPC保护；SJ组的每日写操作预算仍共用。

好家缴费金默认操作尝试上限为30，已有配置不覆盖。领取任务、上报和领奖分别计一次；预算1通常只能签到，无法接着完成浏览和领奖。要跑完整浏览任务需有足够剩余额度。缺少browseTime时按SJ默认15秒完整等待，显式0、负数、错误类型及超过1小时仍跳过。日志显示每项名称、状态、规则是否通过、等待时长、回查结果及余额；首次签到周期缺失、null或空数组不再误判为异常，错误周期结构仍不提交。好家在请求准入后才预留本次额度和回执；被请求上限拦住时记录“未调用RPC”，不新增本次待确认记录。已进入RPC但响应失败/异常仍保留未知记录，旧版本的未知记录不会盲目删除。

农场轮盘在「农场 → 抽抽乐（阿肥寻宝记）」开关，日志入口显示“农场轮盘（抽抽乐）”。无纸阅读和游戏时长正常不能代表轮盘已领奖或抽奖；分别看任务领奖、剩余次数同步、抽奖结果。新修订使用normal模式查询，0次不会发送抽奖，不支持的真实游戏或消费任务继续跳过。

芝麻生活记录优先沿用任务列表中本任务有效的进行中recordId；领取提示已有进行中记录时刷新完整列表再核对，不能只依靠可能属于其他任务的“最近操作”。记录冲突、终态不明或外跳业务未完成时不推送，也不误记未提交失败。好家无忧卡日志现在显示根/组件/订单/资格/任务数量与提交响应；“接口成功校验”不等于已回查完成。

前台小游戏只适配向日葵、这关我很行、三国冰河。支付宝把游戏放到未被监测的独立进程，或无法从前台窗口确认小程序ID时，会停止，不能保证所有版本/设备都可自动操作。乐游记仅操作实际DOM，外跳关卡、挑战和终点大奖请手动处理，不使用截获的MTOP令牌。

任务标题、类型、ID、时长等缺失或变化时停止；亲密度任务只执行明确的APPLET浏览/搜索且服务端提供1～300秒时长，不猜测任务要求。未确认回执写在当前账号runtime状态中，重启或跨日不自动重发，日志会提示；不要将「请求受理」理解为已到账，也不要为重试直接清空整个runtime文件。

这些源码追加已纳入1.2.12，2026-10-07的1.2.11正式包不包含上述新增开关，需安装1.2.12或后续构建。

## 一、安装与启用

1. **前提**：设备已 root，并装好 LSPosed（或兼容框架）。
2. 安装模块 APK。
3. 在 LSPosed 里启用本模块，**作用域勾选「支付宝」（`com.eg.android.AlipayGphone`）**。
4. **重启支付宝**（不是只重启模块），框架才会把新代码注入进去。
5. 打开方式：
   - 桌面图标
   - 或从 LSPosed 的模块列表点进「模块设置」（清单里声明了 `de.robv.android.xposed.category.MODULE_SETTINGS`）

### 需要授予的权限

模块的配置、日志都写在**外部存储**里（原因见 §3），因此必须给足权限：

| 权限 | 用途 | 怎么给 |
|---|---|---|
| **所有文件访问**（`MANAGE_EXTERNAL_STORAGE`） | 读写 `Android/media/com.eg.android.AlipayGphone/sesame-M/` 下的配置与日志 | 模块内会主动跳系统授权页（`PermissionUtil.checkOrRequestFilePermissions`） |
| **闹钟权限**（Android 12+） | 定时执行/唤醒用的精确闹钟 | 模块内会提示（`PermissionUtil.checkAlarmPermissions`） |
| **忽略电池优化** | 防止系统冻结导致定时任务漂移 | 受基础电池优化项控制（`AppConfig.batteryPerm`，默认开） |

## 二、界面结构与"改动怎么保存"

模块 UI 分四级：

| 级别 | 页面 | 作用 |
|---|---|---|
| 一级 | `MiuixMainActivity` | 首页：运行状态、**日志类目与开关**、**模块功能（全局开关，不分账号）**、各分组入口、扩展页入口 |
| 二级 | `MiuixSettingsActivity` | 某账号下的**模型列表**（按分组归类） |
| 三级 | `MiuixGroupFieldsActivity` | 某个**分组**下的**字段列表**（分组与模块基本一一对应；「保护」组含保护、古树两个模块，此时会按模块分小节标题） |
| 四级 | `MiuixSelectionEditActivity` | 集合类字段（选择/多选列表）的编辑，支持多项添加 |

### 保存策略（重要）

**改字段只是写内存，不会立刻落盘。** 落盘统一在**离开页面时**完成：

- 三级/二级页退出走 `saveAndFinish()` → `ConfigV2.save(userId, true)`
- **顶部返回键与系统返回键都会走它**，所以正常返回不会丢改动
- 四级页是 dirty 模式：只有确实改过才在返回时 `applyAndSave()`

⚠️ 因此：**改完配置请用返回键退出页面**，不要在改完的瞬间强杀进程。

### 配置按账号隔离

| 文件 | 内容 |
|---|---|
| `config/<uid>/config_v2.json` | 该支付宝账号的模型配置 |
| `config/<uid>/status.json` | 该账号的当日状态标记（每日自动重置） |
| `config_v2.json`（根目录） | 未识别账号时的默认配置 |
| `config/<uid>/statistics.json` | 该账号的年度／月度／当日统计 |
| `config/<uid>/friendWatch.json` | 该账号的好友收能量统计 |
| `config/<uid>/AutoBlackList.json` | 该账号的自动拉黑、解禁重试记录 |

旧版根目录的同名文件可能混有多个账号的数据，无法可靠拆分；升级后保留原文件作备份，不自动计入任一账号，新账号文件从零开始统计。
`token_config.json` 的答题资料和各类 ID／任务名称映射是共享资料，不是账号统计，仍保留全局。

`<uid>` 是支付宝账号 ID。模块会给每个账号分配一个只增不改的序号，日志里以 `[账号1]`、`[账号2]` 形式出现（对应 `accountIndex.json`）。

> **配置字段增删是安全的**：`ConfigV2.setModelFieldsMap()` 只遍历当前模型声明的字段并搬运旧值，被删除的旧 key 会自动丢弃、不会报错；新增字段首次加载为空。

## 三、数据目录一览

主目录：`/sdcard/Android/media/com.eg.android.AlipayGphone/sesame-M/`

> 用**支付宝的包名**做目录，是为了让「注入进支付宝的模块代码」和「模块自己的 App」两个进程共享同一份数据 —— 它们 UID 不同，只能通过公共位置交换数据（`FileUtil.getMainDirectoryFile()`，`AppConfig` 里也有对应注释）。

```
sesame-M/
├── appConfig.json          界面与日志开关、模块功能开关（全局，不分账号）
├── config_v2.json          默认配置（未分账号时用）
├── config_v2.prev.json     默认配置的写盘前即时快照（见 §9）
├── statistics.json         旧版混合统计（仅保留，不再读取）
├── token_config.json       答题题库 / 光盘图片 / 自定义路线队列
├── config/
│   └── <uid>/
│       ├── config_v2.json  该账号配置
│       ├── config_v2.prev.json 该账号配置的写盘前即时快照
│       ├── status.json     该账号当日状态
│       ├── statistics.json 该账号数据统计
│       ├── friendWatch.json 好友统计
│       └── AutoBlackList.json 自动拉黑记录
├── log/                    日志（见 §5）
├── .nomedia/puzzle/<账号名>/ 拼图验证码截图（隐藏目录；旧 puzzle/ 会自动剪切到这里）
├── bak/                    配置滚动备份（见 §9）
└── *.json                  各类 ID 映射缓存（好友、任务列表、城市码等）
```

另有导出目录：`/sdcard/Download/sesame-M/`（统计/日志/配置的导出出口）。

## 四、配置框架说明

### 4.1 分组

`ModelGroup`：**基础** / 森林 / 保护 / 物种 / 海洋 / 庄园 / 新村 / 农场 / 金豆 / 运动 / 会员 / 经营 / AI答 / 其他，共 14 个。

分组基本与模块一一对应；只有「保护」组下挂了 2 个模块（保护、古树），其余每组 1 个模块。

### 4.2 模型（按注册顺序）

`ModelOrder` 决定顺序：

```
BaseModel(基础) → AntForestV2(森林) → AntFarm(庄园) → AntStall(新村)
→ AntOrchard(农场) → ProtectEcology(保护) → AncientTree(古树)
→ AntDodo(物种) → AntOcean(海洋) → AntSports(运动) → AntMember(会员)
→ GreenFinance(经营) → goldenbeans(金豆夺宝) → AnswerAI(AI答)
→ FishTask(鱼塘) → DayDaySave / LuckCardStatus / FactCheckRewards
→ ForestPlantRewards / PromoprodRewards / WeeklyWelfare / HealthIslandRewards
```

## 五、日志：从哪看、怎么看

### 5.1 位置与文件名

目录：`/sdcard/Android/media/com.eg.android.AlipayGphone/sesame-M/log/<账号名>/`（按账号分目录；
账号名取配置页账号列表括号前面的名字，没有再取括号里面的账号，最后才用 uid，见 `util/AccountFolderName.java`）

每个类目一个文件，**按日期分文件**：`<类目>.<yyyy-MM-dd>.log`

| 类目 | 文件名 | 默认开关 | 内容 |
|---|---|---|---|
| 森林记录 | `forest.<date>.log` | **开** | 森林能量收取、帮收、浇水等 |
| 庄园记录 | `farm.<date>.log` | **开** | 庄园喂养、捐蛋、家庭、答题等 |
| 金豆记录 | `goldenbeans.<date>.log` | **开** | 金豆夺宝相关 |
| 其他记录 | `other.<date>.log` | **开** | 其它模块的动作与**诊断提示** |
| 抓包记录 | `debug.<date>.log` | 关 | 抓包（`Log.debug`），默认不写 |
| 异常日志 | `error.<date>.log` | **开** | 异常堆栈 |
| 运行日志 | `runtime.<date>.log` | **开** | 纯流程：各模块执行过程（按模块打 tag）、调度、配置读写、状态 |

开关在**一级页面**（`MiuixMainActivity` 的「日志」区）。对应的存储字段见 `AppConfig`（`enableForestLog` / `enableFarmLog` / `enableGoldenBeansLog` / `enableOtherLog` / `enableDebugLog` / `enableViewErrorLog` / `enableViewRuntimeLog`）。

### 5.2 写入规则（哪种日志进哪个文件）

| 代码方法 | 运行日志 | 分类文件 | 受哪些开关控制 |
|---|---|---|---|
| `Log.i` / `Log.record` / `Log.system` | ✅（带当前模块 tag） | — | 查看运行日志 |
| `Log.forest` / `Log.farm` / `Log.goldenBeans` / `Log.other` | —（**不再双写**） | ✅ | 对应分类开关 |
| `Log.captcha` | ✅（CAPTCHA tag） | ✅（captcha 文件） | 查看运行日志 + 验证记录开关 |
| `Log.debug` | — | ✅（debug 文件） | 抓包记录（默认关） |
| `Log.error` / `Log.err` | ✅（带当前模块 tag） | ✅（error 文件） | 查看异常日志 + 查看运行日志 |

> **结果只写分类文件、过程只写运行日志**：结果（收取、领取、浇水、兑换、失败应答等）在运行日志里找不到是正常的，去对应分类文件看。
> 「无纸阅读」与「农场游戏时长」按用户需求单独补充运行状态：运行日志也显示开始、成功、失败原因、跳过/停止；成功结果继续保留在森林/农场分类，不受对应分类开关关闭影响而漏掉运行状态（仍需开启「查看运行日志」）。
> 所以"我在日志里找不到"通常是三种原因：① 该分类开关关了；② 看错文件（结果在分类文件、过程在运行日志）；③「查看运行日志」开关关了。
> **诊断提示类信息走 `Log.other`（默认开）**，排查时优先看「其他记录」。

### 5.3 行格式

```
13:34:10.251 FARM: [账号1]执行开始-庄园
19:37:33.150 FOREST: [账号1]真爱浇水🚿给[xxx]合种浇水20g
```

- 前缀是 `时:分:秒.毫秒`，随后是 tag（如果有），再是正文
- **运行日志**的 tag 是模块所属分组（`BASE` / `FOREST` / `PROTECT` / `SPECIES` / `OCEAN` / `FARM` / `STALL` / `ORCHARD` / `GOLDENBEANS` / `SPORTS` / `MEMBER` / `GREEN_FINANCE` / `ANSWER_AI` / `OTHER`），可按模块看流程；宿主、hook 与框架层仍是 `RUNTIME`
- **分类文件**里的结果行带对应分类 tag（例如 `FOREST` / `FARM` / `OTHER`）
- 正文前的 `[账号N]` 是账号简称，便于多账号区分
- 日志**不写 uid、不写本账号昵称**（好友用昵称），便于对外分享

### 5.4 在 App 里查看

一级页点某个类目 → 进入日志查看页：

- 界面保留最近最多 **5000条**，从文件尾部读取最多 **4 MiB**；首次读取走后台。较早内容仍保存在原日志文件，分享/导出取完整文件，不受界面缓存上限影响。
- 支持**搜索**
- **运行日志页额外支持按 tag 过滤**（顶部 Chip，显示各 tag 出现次数）：tag 即模块，可只看某个模块的流程
- 支持**分享**（右上角走系统分享，用 FileProvider 授权，不会暴露其它文件）

### 5.5 日志清理规则

- **关闭某个类目开关时，会顺带清空该类目的历史日志** —— 这是刻意设计，不是 bug
- 每轮任务执行结束后会调用一次清理：**删除所有非当天日志**；当天日志只有在体积 **≥100 MiB** 时才删（`FileUtil.clearLog()`）

### 5.6 用电脑取日志

```bash
adb pull /sdcard/Android/media/com.eg.android.AlipayGphone/sesame-M/log ./log
```

> Windows 下看中文日志若乱码，用支持 UTF-8 的编辑器打开（PowerShell 5.1 默认 GBK 会乱码）。

## 六、自动黑名单

### 6.1 它是干什么的

某些任务在**当前账号/当前版本**下注定做不了（服务端明确不支持、活动当天没配置等）。如果每轮都去试，会产生大量无效请求和误导性的失败日志。**自动黑名单**就是把这类条目自动停掉，并定期放出来复核。

入口是 `MessageUtil.checkResultCodeAndMarkTaskBlackList(列表名, 任务名, 响应)`。

### 6.2 判定规则

新村的「去饿了么果园逛一逛」及浪漫餐厅、青云诀、四季物语三类特定游戏任务，随现有 `closeUnRpc`（默认 true，跳过不支持 RPC 完成的任务）直接跳过自动完成：前者需要实际外跳浏览，后三者需要游戏内订单、闯关或合成事件。运行日志说明跳过原因，不因此写入用户黑名单；服务端已显示完成的任务仍尝试领奖。只按任务类型精确匹配，不按游戏名称屏蔽其它已支持任务。

**先排除可重试错误**（这类只是临时故障，一律不拉黑）：

- 响应里 `retryable` / `retriable` 为 true
- 或 `code`/`resultCode`/`errorCode` 为 `3000`、`REMOTE_INVOKE_EXCEPTION`
- 或文案含「服务器正在开小差」，或 `resultCode=102`（服务端繁忙）

**再按文案判定**，关键字是「不支持rpc调用」：

| 命中位置 | 处理 |
|---|---|
| `desc` 字段 | **立即拉黑**（判据强） |
| 其它字段（`resultDesc` / `resultView` / `memo` / `errorMsg` / `errorMessage` / `resultMsg`） | **需连续确认**：同一项在 3 天窗口内命中满 3 次才真正拉黑；未达标只记录一条「可疑错误第 n/3 次命中」 |

### 6.3 生命周期（四态）

```
尝试 → 失败 → 拉黑 ──(满 3 天)──> 自动解禁、重试一次 ──(再失败，累计满 3 次)──> 永久拉黑
                    └─ 期间每次再失败都重新计时
```

| 参数 | 值 |
|---|---|
| 连续确认次数 | 3 次 |
| 确认窗口 | 3 天（超窗口未再命中则重新计数） |
| 拉黑后解禁 | 3 天后自动解禁并重试 |
| 解禁重试上限 | 3 次，超过则**永久拉黑**，不再自动解禁 |

**只处理模块自动加入的条目**：你自己手动加进黑名单的项，不会被自动解禁打扰。

### 6.4 存储位置

`AutoBlackListMap` 文件，键与值：

```
键：<模块>|<列表名>|<任务名>
值：命中次数;最后命中天;拉黑天;重试次数      拉黑天 = -1 表示永久拉黑
```

### 6.5 受管的 16 个列表

蚂蚁森林活力值任务、蚂蚁森林抽抽乐任务、新版保护地任务、庄园饲料任务、庄园装扮抽抽乐任务、神奇物种任务、神奇海洋普通任务、神奇海洋去摸鱼任务、农场肥料任务、农场抽抽乐任务、网商银行福利金任务、金豆夺宝任务、新村任务、运动任务、会员任务、会员芝麻信用任务芝麻粒。

其中 5 个列表有额外的判据（错误码/特有文案），例如：

- **运动任务**：`TASK_ID_INVALID`、「海豚活动触发不可重试错误」
- **农场肥料任务**：「任务全局配置不存在」
- **会员芝麻信用任务**：「不是有效的入参」「存在进行中的生活记录」「生活记录模板不存在」
- **金豆夺宝任务**：`400000040`、`20020012`、`TASK_ID_INVALID`、`ILLEGAL_ARGUMENT`

### 6.6 在日志里怎么认

配置页黑名单条目标注“手动 / 默认 / 自动 / 自动·永久”。交易、支付、下单、充值、真实履约类任务不发送伪完成请求，关键词命中只跳过，不再据此永久修改黑名单；领奖不受任务尝试次数限制。回查列表失败或结构不明时，只记录“未确认”，不据此增加今日失败标记或自动黑名单。旧版本已经写入的误判项需在对应列表手动移除，升级不会清空用户名单。

关闭对应「自动黑名单」开关后，不再新增自动拉黑或疑似错误的观察记录，包括同轮回查和延迟写入路径；已有黑名单不会因此清空，需要恢复某项时在列表中手动取消勾选。

农场、金豆、会员后备上报的列表核对遇到未知状态时，仅将该任务保留为“未确认”，其余正常任务继续核对。日志会显示 `❓未知任务状态[状态值]`，每种状态在对应模块/列表中每天提示一次；缺失任务ID、坏行等结构异常仍停止整份列表的核对。

关键字：`自动拉黑🏴`（已拉黑）、`自动拉黑🕵️`（疑似、待确认）、`自动解禁🕊️`（解禁重试）、`自动拉黑🔒`（永久拉黑）、`黑名单治理🧹`（原预置项改为自动判定）。

### 6.7 想让它重新尝试

到对应模块的对应列表里，把该项**手动移除**即可；之后走正常流程（若再失败会重新拉黑并重新计时）。

### 6.8 什么时候会记到黑名单（任务尝试策略）

`TaskAttemptPolicy`（`data/task/TaskAttemptPolicy.java`）决定尝试与确认顺序，任务怎么完成、奖励怎么领仍由各模块自己实现。正常尝试及后备完成路径按列表确认；同日已上报但仍待办只防重，不把异步结算延迟作为拉黑依据。业务领奖明确成功直接接受，失败才回查；调用方已经回查的，不再重复查询。

| 情况 | 当日标记 `attempt::<键>` | 自动黑名单 |
|---|---|---|
| 服务端明确做不了（需真实操作） | 打，次日自动恢复 | **不记** |
| 临时故障（`retryable` / `3000` / `REMOTE_INVOKE_EXCEPTION` /「服务器正在开小差」/ `102`） | 不打，留待下一轮 | **不记** |
| 回「不支持rpc调用」（`400000040`） | 先走可用的后备完成路径，同日已上报不重发 | **不因同日仍待办而记** |
| 领奖路径 | 不看当日标记 | 不查黑名单，避免已完成的奖励领不到 |

- 当日标记落在 `config/<uid>/status.json`，跨天自动重置，无需手动清理。
- 兜底记录落在 `runtimeInfo.json` 的 `taskAttemptPolicy.triggeredFallback`，任务消失后保留 7 天再丢弃。

阅读只处理首页免费书籍，按导出协议上报章节阅读时长并查询实际能量进度（不等于真实前台阅读）。不再限制单轮 30 章，有持续能量增长就继续至服务端满额；连续 5 章无增长、章节循环、接口失败或没有未读免费书时停止。单轮运行约 15 分钟后也会暂停，日志说明当前进度，未满额的下一轮仍会尝试；已开始的请求按原超时完成。只有服务端明确返回有效且满额的 current/total 才记录当天完成，不固定承诺 150g。读完的书按账号存于 runtimeInfo.json；在运行日志搜索「无纸阅读」，可看登录/自动获取 Token 是否成功、实际能量变化、当日满额、停止/失败阶段及原因，森林分类仍保留相同状态。C158 实机已反馈进度 59/150，优化后的完整满额流程仍待验证，详见 [SJ 功能移植分析](SJ功能移植分析.md)。

若未取得授权码、登录未返回有效 Token，或接口提示凭据失效/拒绝访问，日志会引导：**支付宝 → 打开对应无纸阅读小程序（appId=`2021003114652763`）→ 完成正常登录/授权 → 等待或重新运行森林任务**，由 M 自动换取新 Token，无需复制或填写。日志区分宿主类/方法不兼容、服务未就绪、缺字段、HTTP/业务错误和网络超时等；宿主不兼容不能靠反复登录保证解决。不会输出 Token、授权码或 miniMark 的值。

## 十一、常见问题排查

**Q：改了配置没生效？**
A：用返回键退出页面让配置落盘，然后**重启支付宝**（跨进程配置靠广播通知重载，重启最稳）。

**Q：日志是空的 / 找不到我关心的内容？**
A：① 确认一级页对应类目的开关是开的；② 通常结果进分类文件、过程进运行日志，「无纸阅读」与「农场游戏时长」的成功/失败状态也进运行日志；③ 诊断类信息在「其他记录」；④ 关掉某类开关会**清空该类历史日志**。

**Q：某个任务一直失败但日志看不出原因？**
A：看「其他记录」与「异常日志」；服务端繁忙（102）会被日志降噪（同 tag 前 3 次打印，之后静默），不是没发生。

**Q：某任务突然不做了，也不报错？**
A：很可能被自动黑名单停掉了。在「其他记录」里搜 `自动拉黑`，并到对应列表里把该项手动移除即可恢复。

**Q：多个支付宝账号会互相覆盖配置吗？**
A：不会，配置、状态、首页数据统计、好友统计和自动拉黑记录均按 uid 分目录（`config/<uid>/`）。旧版根目录的混合数据保留作备份，不自动分配给某个账号。
