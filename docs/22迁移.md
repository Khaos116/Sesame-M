  逛一逛

  不建议迁，理由有三条：

  - 奖励是现金直接入账（每项 0.001 到 0.01 元），比月月赚更明确地落在你删除的范围里。

  - 实现方式是重放抓包序列：8 组页面各自按抓到的顺序发十来个请求，里面写死了素材

    ID、originTraceId、策略码这类一次性值。这些值过期后请求照发但不会入账，而且这种带旧追踪号的曝光上报最像风控会盯的行为。

  - 有真实副作用且无法确认结果：

    - 会替用户订阅冲鸭小程序的三个消息模板（lifemsgprod.message.subscribe）。

    - 会调用快递页的 token.apply/token.consume 和 receiveParcelRewards。

    - 没有任何接口能查到是否入账，日志里的"+0.01 元"全是写死的字符串。

  如果要迁，统一要改的地方

  朋友这份代码不满足 M 的三项硬性规则，不能原样拷：

  - 时间：日期用的是设备默认时区（Locale.getDefault() 加 new Date()），要换成 MyUtils.getInstance()。

  - JSON 创建：全部是 new JSONObject(response)，要换 MyUtils.newJSONObject；请求体是字符串拼接，要改成对象构造。

  - JSON 读取：好运卡里有几处裸 getJSONObject。

  - 切号与取消：用的是 Thread.sleep，要换 TimeUtil.sleep，否则切账号时停不下来；所有 catch (Throwable) 会吞掉取消异常。

  - 结构：朋友是四个独立模块各占一个配置分组。M 的做法是并进 OtherTask，走 OtherRequestGate，带每日预算和回执。

  1. 月月赚的 0.01 元转账红包，算"红包"保留，还是算"现金"不做？

  2. 好运卡开出来的奖励是什么形态？能让朋友给一段开卡成功的响应最好。

  按我的判断，先做赚金币的浏览任务和好运卡，月月赚等你表态，逛一逛放弃。
